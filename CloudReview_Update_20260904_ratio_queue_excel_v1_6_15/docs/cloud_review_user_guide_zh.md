# 云检测筛查与标注工作台

## 已实现能力

- 后台定时递归扫描一个或多个盘阵根目录。
- 按卫星名称前缀过滤数据。
- 自动匹配原始 MSS 影像、综合法 `Cloud.tif`、RDC 掩膜及可选 OmniCloudMask 掩膜。
- 计算每种方法云量、综合法与 RDC 的异或差异比例和 IoU。
- 支持差异优先、日期/难度均衡、最新优先和随机抽样，并设置每日复核总量。
- 支持逐景跳过、整天跳过、从队列中跳着查看。
- 支持选择任一方法、全当前类型、无标注和画笔人工编辑。
- 支持同一掩膜多类别像素值：`0=背景`、`1=云`、`2=雪`、`3=其他`。
- 自动识别同名四波段 `*_L1_MSS.tif`，可按景点击“运行本景”执行 OmniCloudMask。
- 采用后先加入待入库暂存区；正式导入时归档到入库实体目录并写真实 MySQL。
- 支持从真实 MySQL 数据库独立导出训练/验证数据集，已有文件自动跳过。
- 支持把当前影像和掩膜复制到独立的典型数据集目录。
- 定期按保留天数和容量上限清理临时缓存。

## 启动

离线安装包部署时：

1. 解压 `CloudReview_Offline_Win64.zip`。
2. 右键或双击 `Install_CloudReview_Offline.bat`，按提示授予管理员权限。
3. Python 3 和公共库会安装到 `C:\Python310`，不会修改系统 PATH。
4. 应用文件会安装到 `%LOCALAPPDATA%\CloudReview\app`。
5. 安装后从桌面快捷方式 `Cloud Review` 启动。
6. 离线包不再携带演示盘阵数据，首次打开后需要在“设置”中填写内网真实盘阵路径。

源码环境调试时：

```powershell
python scripts/create_cloud_review_demo.py
python run_cloud_review.py
```

软件启动后不会自动访问盘阵，也不会自动扫描：

1. 先在“设置”中确认盘阵、入库实体路径、数据集输出路径和典型数据集目录。
2. 点击“检查环境”。
3. 环境通过后，“扫描一次”和“开始监控”按钮才会启用。
4. 未配置可写入库实体路径或真实 MySQL 时进入测试模式，可以扫描和查看，但不能把标注结果入库。

扫描工作运行在独立 Python 子进程中，不占用 Tk 界面线程。扫描结束后只生成
显示尺寸的叠加缩略图，不会在主界面中处理整幅高分辨率影像。

针对每天上万景数据，扫描器还有三层限制：

- 默认只回看最近 14 天，并在 `年/月/日` 目录层直接跳过更早的整棵目录。
- 单轮最多索引 2000 个新景，达到上限立即停止，下轮从已索引景之后继续。
- 已完成索引且具有空间信息的景只做景号集合判断，不再打开 TIF 或云掩膜。

这些参数可以在设置中调整。

## 空间与时间均衡

程序优先从 `*_meta.xml` 读取四角点和中心经纬度；XML 不可用时，从
`*_L1_MSS.shp` 文件头读取包围框作为回退。数据库保存：

- 四角点、中心经纬度和可配置经纬网格；
- 成像月份和春夏秋冬季节；
- 卫星、训练/验证集和所选云算法。

点击“分布统计”可查看地理网格、月份、季节、卫星、训练/验证及标注类型分布。
队列策略选择 `spatiotemporal` 后，会优先推荐当前数据集中数量较少的
地理网格、月份和季节。入库时训练/验证划分也会参考同一网格和时段的比例。

默认会扫描 `demo_disk_array`。进入“设置”后，将盘阵根路径改成内网 UNC 路径，例如：

```text
\\perform03.product\w\GSHC2IMPS\PRODUCT
```

多个根路径用英文分号分隔。卫星前缀用英文逗号分隔。

## 文件识别约定

一个完整场景至少需要原始 MSS 影像和两个同名云掩膜。程序按路径区分两种方法：

```text
景目录\同名景子目录\*_L1_MSS.jpg（或 tif）
景目录\同名景子目录\Debug\Cloud\combined\*.tif             # 综合判别法（优先）
景目录\同名景子目录\*_L1_MSS_Cloud.tif                     # 综合判别法（兜底）
景目录\同名景子目录\Debug\Cloud\dst512\*_L1_MSS_Cloud.tif  # RDC
景目录\同名景子目录\Debug\Cloud\dst_omni512\*.tif          # Omni（如已生成）
```

程序忽略大小写，并按完整景号跨子目录归并文件。路径包含
`Debug\Cloud\combined` 的 tif 会优先识别为综合判别法；没有该目录或
没有结果时，再使用景目录下的同名 `Cloud.tif`。路径包含
`Debug\Cloud\dst512` 的同名 `Cloud.tif` 会识别为 RDC。

## 按景运行 OmniCloudMask

程序在每个产品的同名 L1_MSS 子目录中识别原始分辨率四波段
`*_L1_MSS.tif`。点击 OmniCloudMask 卡片下的“运行本景”后：

1. 后台只运行当前这一景，不会递归处理整天数据。
2. 按吉林一号 B/G/R/NIR 波段顺序读取，并使用 R/G/NIR 推理。
3. 结果写入缓存目录的 `omnicloudmask` 子目录。
4. 推理结束后第三列立即显示结果，可直接选用或人工编辑。

“Omni 推理 Python”可以留空。软件会依次检查当前 Python、常见
Anaconda/Miniconda 路径，并且只有在 `rasterio`、PyTorch、`timm`、
`segmentation_models_pytorch` 等依赖均可导入时才会使用该环境。

OmniCloudMask 4.0 还需要在“Omni 模型目录”中放置两份本地权重：

```text
PM_model_OCM_7.97_R_G_NIR_3_smp_regnety_004.pycls_in1k_PT_state.safetensors
PM_model_OCM_7.97_R_G_NIR_3_smp_edgenext_small.usi_in1k_PT_state.safetensors
```

软件会在运行前检查文件是否存在且大于 1 MB。权重不完整时不会在内网
尝试联网，而是立即显示缺失文件清单。

## 闭合轮廓编辑

掩膜编辑器提供两种形状：

- “画笔”：按画笔宽度连续增加或擦除云。
- “闭合轮廓填充”：按住鼠标圈选，回到黄色起点附近松开鼠标，曲线会自动闭合并填充成面。

选择“增加标注”时会按主界面当前标注类型写入对应像素值，选择“擦除标注”时整个闭合区域写为 0。

## 入库与数据集导出

标注成果分成两个环节处理：

1. “加入待入库”只写入候选暂存区，不写正式 MySQL 记录，也不生成训练集。
2. 在“待入库管理”中确认后点击导入，软件会把影像和标签归档到：

```text
入库实体路径\DataAll\DataCG\YYYYMMDD\rgb
入库实体路径\DataAll\DataCG\YYYYMMDD\label
```

归档时文件名保持来源文件名，数据库中的 `jpg_path` 和 `label_path`
记录这份长期保存的实体路径。归档成功后再写 MySQL；如果 MySQL 失败，
本次归档文件会回滚删除，候选记录保留，便于修复连接后重试。

“导出数据集”是独立按钮。它从真实 MySQL 的 `jpg_path`、`label_path`、
`sat`、`tra_val` 读取记录，复制到：

```text
数据集输出路径\train\rgb\数据库id.tif
数据集输出路径\train\label\数据库id.tif
数据集输出路径\val\rgb\数据库id.tif
数据集输出路径\val\label\数据库id.tif
```

目标路径里已有的图像或标签不会重复复制；每次导出都会生成
`manifest.jsonl`，方便训练脚本读取。

“数据集标签编码”可在设置中修改：

- `binary255`：任意非 0 标签输出为 255，兼容原来的云二分类数据集。
- `class_values`：输出 `0=背景, 1=云, 2=雪, 3=其他`，适合多类别训练。
- `preserve`：原样复制数据库中的标签文件，不做像素值转换。

## 数据安全

正式入库成果由两部分共同组成：

- “入库实体路径”保存实际的 JPG/TIF 影像和标签文件。
- MySQL 的 `cloud.path` 表保存每条记录的 `sat`、`tra_val`、
  `label_path` 和 `jpg_path` 等字段。

默认 MySQL 配置兼容原 `cloud.py`：`localhost:3307`、用户 `root`、
数据库 `cloud`、表 `path`。密码及其他连接参数可在“设置”中修改。
点击“检查环境”时会同时检查入库实体路径写权限和 MySQL 连接。软件不会强制
改造旧表结构；写入时会自动识别表里已有字段。若你后续给旧表增加
`upper_left_lon`、`upper_left_lat`、`upper_right_lon`、`upper_right_lat`、
`lower_right_lon`、`lower_right_lat`、`lower_left_lon`、`lower_left_lat`
等四角点字段，软件会自动填入。

- “加入待入库”只写入候选暂存区，不写正式 MySQL 记录。
- “待入库管理”可以预览、剔除、导入选中或全部导入。
- 正式导入时先复制文件，再写 MySQL；MySQL 失败会删除本次正式复制文件，
  候选记录继续保留，便于修复连接后重试。

- 扫描与排队阶段只记录源文件绝对路径，不复制源数据。
- 只有点击“选用”、全当前类型、无标注或确认人工编辑后，才复制影像和最终掩膜到待入库缓存。
- SQLite 保存复核状态，程序重启后不会把已入库场景重新排入待复核队列。
- 训练/验证划分按场景 ID 的稳定哈希生成，同一景重复整理时划分不会漂移。
