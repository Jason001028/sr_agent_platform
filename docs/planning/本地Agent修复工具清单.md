# 本地 Agent 逐景修复工具清单

适用于 Viewer 的「Agent 协助」入口。用户确认批次计划后，本地 Agent 逐轮选择影像和动作，工具直接调用部署环境的真实 SR 服务。计划沿用原始序号及排除项，Goal 记录批次，Item 记录单景，Job 记录一次 SR 作业。

本文是开发清单。下表的“现有”表示仓库已有对应能力，“适配”表示需要把已有服务接入 Agent 执行路径，“新增”表示拟开发的接口。新工具名为建议名。首版按每轮一个动作、一个 SR 在途设计，等待 SR 或人工复核期间可以处理其他景。

## 首版必须新增的四个工具

四个接口都由本地 Agent 主动调用，当前 Goal 由运行器绑定，模型传入 `item_id`。以下顺序可以直接作为真实单景的联调顺序。

| 开发项 | 首要实现工作 | 验收时查看的结果 |
| --- | --- | --- |
| ① `detect_repair_item` | 按计划选定的策略检测本景，将检测记录和区域引用写入 Item | 有候选时能继续构建 Mask；无候选时按策略结束或进入整景复核；缺输入时能说清缺哪份影像 |
| ② `build_repair_mask` | 读取本次检测记录，生成或关联候选 Mask，发布给 Viewer | 用户能定位候选区域；部分通过后，提交步骤能取得只包含通过区域的有效 Mask |
| ③ `submit_repair_item` | 从就绪 Item 装配真实 SR 参数，复用单景提交意图、资源占用和作业绑定 | 返回可查询的真实 Job ID；重启后能找回同一次提交及其关联 Mask |
| ④ `verify_repair_output` | 对本次 Job 执行产物校验，关联成果和人工审核记录 | 校验通过时可从 Viewer 打开本次输出；缺件时指出缺失项；质量验收取自人工决定 |

建议先贯通③的 Item → Job 绑定。它决定④验证哪一次输出，也决定服务重启后运行器接续哪一个作业。其余动作的依赖顺序和现有工具的接入点见下表。

真实 SR 产物通过契约验证后，进入独立的[修复效果对比工具开发需求](#repair-effect)。它为人工复核提供逐区域的模糊和伪影变化证据。

## 1. 完整调用清单

| 阶段 | 工具及开发方式 | 调用时机与主要输入 | 回执和业务效果 |
| --- | --- | --- | --- |
| 确定范围 | 现有 `get_repair_workspace` | 用户引用“这批”“当前选中”时，读取消息绑定的工作区 | 确定清单身份、范围及已有任务 |
| 准备计划 | 现有 `prepare_repair` | 明确要求修复时，传入范围、排除项和修复策略 | 生成可确认计划及准入结果；卡片显示缺项 |
| 读取批次 | 适配 `query_batch_repair` | 传入当前 Goal；每轮由运行器注入同源摘要，用户追问时也可直接查 | 当前计数、在途 Job、待审项、可做动作涉及的 Item；较长清单按需分页 |
| 定位单景 | 现有 `list_repair_items`、`get_repair_item` | 按状态分页找景，或读取指定 Item 的详情与复核有效性 | 得到原始序号、稳定 Item ID、检查点及阻塞原因 |
| 检测 | 新增 `detect_repair_item` | 对待检测 Item 调用；从计划读取检测方法，从 Item 解析目标及参考影像 | 保存检测结论、候选数、区域引用。无候选按计划结束或进入整景复核；缺输入记录具体缺项 |
| 构建候选 Mask | 新增 `build_repair_mask` | 传 Item ID，使用该景当前检测结果 | 写入候选区域与工件引用。需要人工复核时生成 Viewer 可打开的待审项；已有指定 Mask 的景沿用计划对应入口 |
| 提交真实 SR | 新增 `submit_repair_item`，适配真实提交服务 | 传就绪 Item ID；服务按计划和当前有效 Mask 装配参数 | 绑定实际 Job ID、提交意图和回执。已有本次提交时返回其记录；提交结果未知时先对账 |
| 查询作业 | 适配 `sr_job_status` | 对已有 Job 到期查询；由应用层绑定对应 Item | 排队或运行中写下次查询时间；成功转产物验证，失败记录执行原因 |
| 验证并发布成果 | 新增 `verify_repair_output` | 传 Item ID，读取其本次 Job 和产物回执 | 写入执行、契约及产物验证结果，关联可打开的成果；按现有规则创建质量审核记录 |

四个新增工具均以当前 Goal 为执行上下文。批量选择由 Agent 完成，每次工具调用只对一个 Item 生效。算法工件保存在本地，模型读取引用、计数和摘要。检测或构建服务若一次已生成可用 Mask，后续步骤直接关联该工件。

## 4. 部署交付核对

- [ ] **真实单景跑通。** 在部署环境确认一景计划，跟踪检测、Mask、区域复核、真实 Job、产物验证和 Viewer 成果入口。可按 Item 查到每一步回执。
- [ ] **多景能推进。** 使用含排除项和需复核景的清单。某景等待时继续处理其他景，清单原序号稳定；无候选或失败景有具体结论。
- [ ] **复核能接续。** 在 Viewer 仅通过部分候选区域，确认提交使用对应版本的 Mask；成果质量决定单独记录。
- [ ] **真实作业能恢复。** 在已有 Job ID 时重启平台，运行器恢复跟踪同一 Job，后续验证和结果展示关联同一次作业。
- [ ] **反馈能解释决策。** 从侧舱点开任一景，能看到上一步工具给出的事实、随后执行的动作，以及当前完成或等待的原因。

## 6. 独立开发需求：评估修复前后的模糊与伪影

**拟新增工具 `assess_repair_effect(item_id, job_id)`。** Agent 在 `verify_repair_output` 确认该 Job 的输出可读后调用。用户打开「前往复核」时，应能直接看到哪块区域变清晰、哪块仍有条纹、哪块虽然更锐却出现了光晕。工具生成传统 CV 对比报告，人工质量决定继续由 Viewer 记录。

### 比较对象与计算范围

- 从 Job 回执和 Item 工件引用解析**本次修复前的目标本体备份、本次修复后的本体、实际提交的 Mask**。RC、SC 按本次目标身份解析。NOSR 可辅助定位纹理，前图必须对应本次写回之前的本体。缺少可追溯的前图时返回“无法比较”及缺项。
- 在目标本体像素网格上，按有效 Mask 的连通区域成对读窗，保留一圈上下文用于测边缘和边界变化。同一窗口使用相同波段、浮点 DN 和共同的强度尺度。用 Mask 外稳定纹理检查配准；前后错位或有效像素不足的区域标为“证据不足”。
- 分块读取原始分辨率 TIFF。计算时排除 NoData、饱和像素；有可用云水掩码时记录遮挡比例。平坦区可用于观察噪声与条带，其清晰度结论取决于可匹配边缘数量。

### 首版指标及判读

| 观察项 | 成对计算方法 | 如何解释 |
| --- | --- | --- |
| 模糊 | 在修复前选取有对比度的孤立边缘，沿法线在前后图同一位置采样。比较匹配边缘 10%～90% 灰度过渡宽度的中位数，同时记录有效边缘数。以局部方差图观察纹理变化 | 宽度缩小支持清晰度改善。方差上升也可能来自噪声，需结合伪影指标判断 |
| 振铃／过锐光晕 | 用同一批边缘两侧的稳定灰度估计上下平台，比较沿边缘法线的过冲、欠冲幅度，以平台灰度差归一化 | 原有过冲减弱支持光晕改善；边缘变窄同时过冲加重时，分别报告两种变化 |
| 条带 | 对低纹理有效区去除缓变背景，沿行、列计算残差的稳健均值序列，比较前后条带幅度和连续影响范围；记录方向 | 原有方向上的条带减弱支持改善。结构密集、可用背景不足时标明该指标不可判 |
| 新增噪声与拼接痕迹 | 对同一平坦区比较高频残差的中位绝对偏差；在 Mask 边界成对比较跨边界亮度跳变，并保留定位框 | 用于识别“变锐但噪声增加”和局部修复引入的新接缝 |

参考脚本以 PAN 与 NOSR 做局部模糊检测。其 `compute_local_variance` 和 `blur_test_byfre` 提供了局部方差图、分块频域分析的参考，`detect_stripe` 提供条带形态分析思路。本工具改为同一目标前后配对，并以人工标注的真实 ROI 校准变化阈值。脚本中的绝对 DN、像素面积和频段常数依赖输入尺度。[参考脚本](../../SR_code/recovered_blur_detection_29_images.py)

### 输出与 Agent 后续动作

每个区域返回编号、坐标、有效样本量、指标前值／后值／差值、分项结论，以及使用的算法与阈值版本。在同传感器、同网格和同类型区域上，依据未变化对照及人工标注设定各指标的最小可辨变化。目标缺陷减轻且其他指标稳定时记“改善”；变化处于容差内记“无明显变化”；新增或加重缺陷记“恶化”；清晰度与伪影变化方向冲突记“混合”；缺少可靠比较基础记“证据不足”。校准前输出原始测量值供复核。

单景摘要按结论统计区域数和覆盖面积，并优先列出恶化、混合及证据不足区域。Viewer 提供同尺度、同拉伸的前后裁片与定位框，Agent 可引导用户跳到具体区域。报告绑定 Item、Job 和 Mask 版本，支持回看某次修复的证据。

### 验收用例

- [ ] 同一窗口前后完全相同，有效指标差值为零，结论为“无明显变化”。
- [ ] 对有清晰边缘的原图施加已知模糊，将模糊图作前图、原图作后图，测得边缘变窄；交换顺序后方向反转。
- [ ] 分别构造条带减弱、锐化产生光晕和局部新增接缝的成对窗口，检查对应区域、方向与指标；锐化伴随明显过冲时能显示混合结果。
- [ ] 对纯平坦、遮挡或前后错位区域显示具体证据缺口；多区域混合场景能单独找出恶化的小区域。
- [ ] 从一次真实 SR Job 的复核入口对照原始裁片，核实备份、输出、Mask 版本及定位框，并用人工逐区结论记录误判和漏判。
