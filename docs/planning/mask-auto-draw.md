# 差异热力图掩码自动绘制方案（调研）

> 日期：2026-11-06 · 状态：草稿（仅方案，未实现）

## 1. 需求与边界

差异定位产生热力结果后，在「差异定位」附近增加半透明「自动绘制」按钮。点击后：

1. 对每处高亮区域逐一画一个**外接多边形**，绘制过程实时可见；
2. 多边形比区域略大，但面积不能明显夸张；
3. 顶点数受控，不出现上百个折点的轮廓；
4. 画出的多边形进入该影像的人工掩码列表，后续「生成掩码 / 保存掩码到盘阵」照旧由用户显式触发。

不改变的口径：

- 自动绘制只写内存里的 `rec.maskRois`，不写 `mask.tif`，不自动提交 SR；
- 仍遵守「掩码只画在本体影像（`stageKind === 'input'`）上」；
- 分析结果仍可只读浏览，自动绘制是用户显式动作，不是分析结束就自动落掩码；
- 掩码是**覆盖型**多边形：它保证包住高亮区域，不承诺等于原始 DN 的精确边界。

## 2. 可复用的现有件

| 位置 | 能力 | 备注 |
|---|---|---|
| `backend/services/image_diff.py` `_regions` | 8 邻域连通域、每区域 bbox / label / 面积 | 自动绘制必须**按 label 逐个**处理；拼在一起的多个连通域只追踪第一个 |
| 同上 `_trace_outer` | Moore-Neighbor 外轮廓追踪 | 输入要求四周有 ≥1 px 背景 |
| 同上 `_rdp` | 闭合多边形 Douglas-Peucker | 按离首点最远顶点拆两条开放折线，首尾重合不会退化 |
| 同上 `_polygon_iou` / PIL 4× 栅格化 | 多边形与真实掩码的覆盖核对 | 可改成「区域是否被多边形完全覆盖」 |
| `scipy.ndimage.distance_transform_edt` | 精确欧氏距离变换 | 已在 NoData 重采样中使用，SciPy 为必需依赖 |
| `frontend/src/lib/maskgen.ts` | `traceContour` / `simplifyPoly` / `fillRegionHoles` / 扫描线栅格化 | 前端已有一套同类实现，可作为降级或测试对照 |
| `viewer.addMaskPolygon` | 把多边形写进 `rec.maskRois` | 坐标为**缩略图**坐标 |
| `lib/diffLocate.ts` `gridPointToThumb` | 分析网格 → 缩略图坐标 | 预览范围裁剪与原始 ROI 都已处理 |

坐标链：后端分析网格（可能是预览下采样，也可能是原始 ROI）→ `gridPointToThumb` → 目标影像缩略图 → 生成掩码时 `thumbToOrig` 放大到源影像尺寸。多边形在缩略图上只是坐标载体，放大后仍保持相对区域的边距。

## 3. 候选算法对比

### 3.1 候选

| 方案 | 做法 | 优点 | 问题 |
|---|---|---|---|
| A. 缓冲区 + 轮廓追踪 + RDP | 区域栅格先按边距 `m` 膨胀（EDT 阈值），填洞，Moore 追踪，RDP 简化到顶点上限 | 保形最好；边距均匀；复用现有追踪/简化；覆盖可核对 | 每区域多做一次距离变换与简化 |
| B. 凸包 + RDP | 膨胀后取凸包，再简化 | 顶点少；实现简单 | 凹形、L 形、月牙形大面积过覆盖，面积比可达 1.8–2.2 |
| C. 最小外接旋转矩形 | 旋转卡壳求最小面积矩形，再向外留边距 | 4 个顶点；细长条状伪影很贴合 | 对弯曲、L 形、月牙形过覆盖；不适合作为统一默认 |
| D. 轴对齐外接矩形 | bbox 四边各加 `m` | 4 个顶点；极简单 | 斜向细长条面积极度夸张（实测 28 倍） |
| E. Alpha shape / 凹包 | Delaunay + α 阈值取凹包 | 边界最贴近真实形状 | 参数敏感、顶点多；不保证包含全部区域；SciPy Delaunay 成本高 |
| F. 原轮廓按质心放大 | 以质心为中心缩放 `contour` | 代码最少 | 边距随离质心距离变化；细长形两端够、腰部不够，不能保证覆盖 |

### 3.2 合成形状实测

在 300×300 网格上构造代表性形状，边距公式见 §4.1，简化目标 12（到达容差上限时允许超出，不为了凑顶点数切掉区域），结果如下（`ratio` 为多边形面积 / 区域面积；环形区域同时给出按填洞后面积的比值）：

| 形状 | 缓冲区+RDP 面积比 / 顶点 | 凸包 面积比 / 顶点 | 轴对齐 bbox 面积比 | 最小外接矩形 面积比 |
|---|---|---|---|---|
| 椭圆斑块 120×80 | 1.12 / 12 | 1.12 / 12 | 1.54 | 1.51 |
| L 形 80×90 | **1.15 / 6** | 1.85 / 9 | 2.72 | 2.66 |
| 4 px 斜向划痕 | 1.65 / 7 | 1.65 / 10 | 27.95 | 1.70 |
| 圆环 r40 厚 6 | 3.67 / 16（按填洞面积 1.01） | 3.45 / 9（缺口 120 px） | 5.09 | 4.87 |
| 月牙形 | **1.20 / 15** | 2.19 / 12 | 2.76 | 2.71 |
| 8×8 小方块 | 1.23 / 8 | 1.23 / 8 | 1.56 | 1.27 |
| 260×2 细长条 | 1.50 / 6 | 1.50 / 8 | 2.02 | 1.51 |

结论：

- 缓冲区方案在凹形、L 形、月牙形上明显优于凸包与矩形；对细长条与最小外接矩形接近。
- 轴对齐 bbox 在斜向细长目标上不可接受（面积放大 28 倍），不能作为兜底。
- 凸包在圆环上经 RDP 简化后漏掉 120 px：**顶点压缩不能以牺牲覆盖为代价**，任何简化后都必须做覆盖核对。
- 缓冲区方案在圆环、斑块、月牙上做覆盖核对时分别需要把边距加 1 px 才能做到 100% 覆盖；核对与重试是必需步骤，不是可选项。
- 合成里把两个相距 10 px 的方块放进同一张掩码时，`trace_outer` 只追踪第一个连通域，另一块整块漏掉（漏 1600 px）。这说明自动绘制必须**逐 label**生成多边形，不能拿全幅二值掩码直接追轮廓；生产代码的入口是 `labels` 而不是 `binaryMask`。

进一步按「覆盖 100% + 简化目标 12」重跑缓冲区方案：

| 形状 | 初始边距 m | 实际用边距 | 顶点 | 面积比（填洞后） | 漏覆盖 px | 区域到多边形边界的最小内距 |
|---|---|---|---|---|---|---|
| 椭圆斑块 | 4.34 | 5.34 | 10 | 1.13 | 0 | 1.00 |
| L 形 | 2.74 | 2.74 | 6 | 1.14 | 0 | 2.00 |
| 4 px 斜向划痕 | 1.45 | 1.45 | 6 | 1.65 | 0 | 1.41 |
| 圆环 | 1.88 | 2.88 | 12 | 1.07 | 0 | 1.00 |
| 月牙形 | 3.42 | 4.42 | 15 | 1.29 | 0 | 1.00 |
| 8×8 小方块 | 1.00 | 1.00 | 8 | 1.23 | 0 | 1.41 |
| 260×2 细长条 | 1.00 | 1.00 | 6 | 1.50 | 0 | 1.41 |

月牙形顶点 15，是因为把简化容差限制在 `0.9m` 以内、到达上限后不再压缩；这比为了 12 个顶点切掉区域更符合「外接」要求。建议顶点上限设为 16，复杂形状允许到 24，仍不行再回退凸包并标注。

单区域生成耗时（合成形状、本机 Python 3.11 + SciPy 1.10，含覆盖核对）：40×40 约 4.6 ms、80×60 约 6.2 ms、160×120 约 25 ms、400×300 约 39 ms。按前 16 个区域估算约 0.1–0.6 s，属于可接受但可感知的增量（见 §5）。

## 4. 推荐方案

### 4.1 参数

以「填洞后的区域面积」`A` 和区域 bbox 短边 `d` 计算边距（单位均为分析网格像素）：

```text
m = max(1.0, 0.05 * sqrt(A))
m = min(m, 20.0, max(1.0, 0.10 * d))
```

（`d` 为区域 bbox 短边；写成这个顺序，细长区域的下限仍是 1 px，不会被 `0.10d` 压到 0。）

- 小区域（如 8×8，A=64）取 1 px，面积比约 1.23，不会因固定像素边距把小块撑得很大；
- 中等区域按面积开方取比例，边距随区域一起缩放，换预览档位或原始 ROI 时不改变相对观感；
- `0.10 * d` 与 20 px 两道上限防止细长区域或超大区域边距失控；
- 边距是分析网格像素；映射到源影像后会随共同网格缩放同步放大，因此不需要在原始像素上另算一套。

顶点上限：

```text
MAX_VERTICES = 16            # 目标
MAX_VERTICES_HARD = 24       # 形状复杂时的上限
```

简化容差从 `max(0.4, 0.35m)` 起步，按 1.25 倍递增，**不允许超过 `0.9m`**。RDP 的弦到原轮廓最大偏差不超过容差；连续几何下，容差小于边距可以给覆盖留出余量。像素中心追踪、距离变换的离散边界与 4× 栅格化还会吃掉半像素到 1 px，所以覆盖核对与重试是必需步骤。若更在意「一次通过」，可把容差上限收紧到 `0.6m`；实测这样不再需要加边距重试，但简单形状的顶点会变多（斑块 10 → 16、圆环 12 → 20），因此默认仍取 `0.9m` + 核对重试。

### 4.2 单区域流程

```text
输入：labels、区域元数据 r（x/y/w/h/label）、填洞后的区域 sub
1. 计算 m（§4.1）
2. pad = ceil(m) + 2；把 sub 放进带背景边框的 padded 数组
3. buf = distance_transform_edt(~padded) <= m
4. buf = binary_fill_holes(buf)          # 外接多边形必须封住孔洞
5. traced = _trace_outer(buf)            # Moore-Neighbor
6. eps = max(0.4, 0.35m)；simp = _rdp(traced, eps)
   只要 |simp| > 16 且 eps < 0.9m：eps = min(0.9m, eps * 1.25)，重新简化
7. 去掉近似共线点（只在不会明显内移边线时合并）
8. 坐标回到分析网格：x + r.x - pad, y + r.y - pad
9. 在 4× 栅格上核对：
   - 原始区域像素是否全部被多边形覆盖：必须 100%
   - 多边形面积 / 填洞后区域面积是否 ≤ 1.8（小区域可放宽到 2.2）
   - 顶点数是否在 [3, 24]；多边形是否简单（非相邻边不相交）
10. 不通过：m += 1，回到 3，最多重试 3 次
11. 仍不通过：回退到「膨胀区域的凸包 + 受控 RDP」，再核对；
    再失败则放弃该区域并计入 skipped，不写外接矩形兜底
```

几个要点：

- **逐 label 处理**。把整幅二值掩码一起膨胀会把相邻区域连成一个多边形，也会让「每处高亮区域逐一绘制」变成「一团」。本仓库的 `_trace_outer` 只追踪第一个连通域，更不能直接喂全幅掩码。
- **先填洞再膨胀**。当前掩码模型是多边形并集，没有「挖洞」语义；外接多边形天然会把孔洞覆盖掉。需要把孔洞像素数记进结果并在提示里说明，不要把它说成精确边界。
- **覆盖核对用区域不是轮廓**。只核对「简化多边形是否包含原始连通域」，不追求与轮廓 IoU 高；外接多边形的目标就是略微超出。
- **边界区域**：区域贴分析网格边缘时，padding 会补出背景，多边形可能落到网格外；掩码栅格化会自然裁掉，缩略图绘制也会裁到画布，不需要强行夹紧（夹紧反而可能切掉区域）。
- **邻近区域**：各自独立膨胀，多边形可以重叠；掩码是多边形并集，重叠无害，不要为了去重把两块合成一个。

### 4.3 为什么默认不用凸包

凸包是合法外接多边形，顶点也少，但对凹形目标的面积膨胀明显（L 形 1.85、月牙 2.19，按填洞面积更高），与「不能太夸张」冲突。凸包只作为「缓冲区轮廓顶点压不下来」时的兜底，并在结果里标出 `fallback: 'hull'`，便于 UI 或日志区分。

### 4.4 与现有「加入掩码」的关系

现有 `addRegionToMask` 拒绝 `outer`（含孔洞）、`approx`、`bbox` 轮廓，因为那些轮廓要么表达不了孔洞，要么与真实区域偏差大。自动绘制生成的是**覆盖型多边形**，语义不同：它主动接受孔洞被填、主动留边距、主动简化，所以不能复用那条拒绝逻辑；但也不能因此把自动绘制说成「精确掩码」。两者在 UI 上应分开描述：单区域「加入掩码」是精确区域，自动绘制是覆盖区域。

## 5. 计算位置与接口

推荐在**后端**生成，作为 `/api/diff/analyze` 结果的可选字段返回；前端只做映射与动画。

理由：

- 后端已有 `labels`（每个区域的精确 label），逐区域膨胀、填洞、追踪、简化、覆盖核对都能直接复用 SciPy 与现有 `_rdp` / `_trace_outer` / PIL 栅格化；前端只有二值掩码并集，需要重新做按区域洪泛、膨胀与核对，重复且容易与后端口径分叉；
- 掩码几何会写进 SR 输入，保持「形态学、连通域、轮廓固定走 SciPy」的确定性口径；
- 前端在动画开始前拿到全部多边形，绘制节奏稳定，不需要边算边卡。

代价是分析响应多一次计算。为了控制耗时：

- 只对**排序后的前 `AUTO_MASK_MAX_REGIONS = 16` 个区域**生成；其余区域仍可单区域「加入掩码」或手工绘制。结果级另给 `autoMaskSummary: { totalRegions, drawnRegions, skipped }` 计数，区域级只带成功的 `autoMask`；
- 每个区域只处理自己的 bbox + 边距 + padding，不做全幅距离变换；
- 实测单区域 4–40 ms，前 16 个约 0.1–0.6 s；若真机盘阵上耗时不可接受，再把上限降到 8 或改为用户设置。

建议字段（可选，旧服务不返回时前端隐藏按钮）：

```json
"autoMask": {
  "contour": [[x, y], "..."],
  "marginPx": 2.74,
  "vertexCount": 6,
  "areaRatio": 1.14,
  "coverage": 1.0,
  "filledHolePx": 0,
  "fallback": "buffer"
}
```

`contour` 是分析网格坐标，不重复首点；`areaRatio` 相对填洞后的区域面积；`coverage` 为区域被覆盖比例（应为 1）。前端 `DiffRegion` 增加可选 `autoMask` 字段。`/api/diff/analyze` 的请求可增加可选的 `autoMask: { maxRegions, maxVertices }`，默认值即上表；不传时行为固定。

旧后端兼容：没有 `autoMask` 字段时不显示「自动绘制」，不做「用旧 `contour` 假装外接」的降级——旧轮廓可能切掉区域，和按钮承诺不一致。后端有字段但个别区域失败时，前端只画成功的，提示跳过数量。

### 5.1 前端实时计算的取舍

另一条路是不改后端：按钮点击时从已解码的 `binaryMask` 取每区域 bbox，做洪泛填洞、JS 距离变换/膨胀，再复用 `maskgen.ts` 的 `traceContour` / `simplifyPoly` 与 4× 核对。

- 好处：分析响应不变慢；点击后才算，可按用户当前意图只算前几处；边距参数可即时调。
- 代价：前端只有二值并集、没有每区域 label，得靠 bbox + 洪泛恢复连通域（虽然 8 邻域 label 分离时不会串区，但多一层假设）；距离变换、覆盖核对要在 JS 重写一遍，和 SciPy 的口径容易分叉；大网格 + 多区域的点击瞬间可能卡主线程，除非再拆到 Worker。
- 结论：不作为首选。若后续发现后端增量不可接受，可先按这个方向做只算前 8 处的降级版，算法仍沿用 §4。

## 6. 交互与动效

### 6.1 按钮

- 位置：工具栏「差异定位」右侧的同一组工具键，排在「延续到下一景」之后，保持「差异定位 → 延续 → 自动绘制」的稳定顺序；「延续到下一景」仍紧挨「差异定位」。
- 视觉：沿用鹰眼工具键——28 px 高、8 px 圆角、`--tb-*` 令牌、浅阴影、默认 `opacity: .45`，悬停 / 键盘聚焦恢复 1；实现上抽一个共用样式或共用组件，避免与 `DiffContinueButton.vue` 两份重复。
- 出现条件：有结果、显示方式为独立热力图或热力叠加（`showHeat`）、单图、未进入绘制模式、结果未过期（`!stale`）、`autoMask` 至少有一个可用区域。与「延续到下一景」的视觉与交互一致，但不要求存在下一景。
- 无可用区域或 A/B 里没有本体影像时禁用，`title` 说明原因；不悄悄消失。
- 点击后按钮进入「绘制中…」并显示进度（如 `3/12`），动画结束或取消后恢复。

### 6.2 目标影像

- 掩码只能写本体：在结果的两张影像里找 `stageKind === 'input'` 的那张（A 优先，其次 B）。两张都是中间产物（SR / NOSR）时禁用，并提示「当前配对没有可写掩码的本体影像」。
- 目标不是当前活动影像时，先 `viewer.activate(targetId)`，再进入绘制模式；热力图会继续画在这张图上（`diff.layerFor` 已按结果身份判断）。
- 坐标映射统一用 `gridPointToThumb(res, x, y, target.thumb.width, target.thumb.height)`，不把分析网格当原图坐标。

### 6.3 绘制过程

- 点击后调用 `viewer.enterDraw()`：ROI 层只有在绘制模式下才常显；自动绘制的产物应当立刻可见、可调整、可删除，因此进入绘制模式是行为的一部分。进入前已确认目标是本体，`enterDraw` 的中间产物拒绝不会误伤。
- 按 `regions` 的 rank 顺序逐个画：每个多边形只用 SVG 描边做「笔迹生长」，不每一帧重绘整个 TifCanvas；画完一个再 `viewer.addMaskPolygon` 落进 `maskRois`，然后画下一个。
- 配色与绘制模式一致：白色 2.8 px 底描边 + `#D94752` 1.4 px 主描边；可加一个 3 px 的笔尖圆点。多边形完成后由 TifCanvas 接管常显，SVG 移除该段，避免双重描边。
- 节奏：新增 `lib/motion.ts` 常量，例如 `AUTO_DRAW_TOTAL_MS = 3200`、`AUTO_DRAW_STEP_MIN_MS = 140`、`AUTO_DRAW_STEP_MAX_MS = 480`、`AUTO_DRAW_GAP_MS = 60`；按各多边形周长分配时长，总预算封顶，超过预算的部分直接落笔不动画。缓动用 `linear` 模拟运笔，最后可加一点 `easeOutCubic` 收笔。
- `prefers-reduced-motion: reduce`：不播放笔迹，直接逐个落进 `maskRois`（或一次性批量落），仍进入绘制模式。
- 动画期间允许缩放和平移（覆盖层随 `thumbToScreen` 重算）；换活动影像、切场景、清除结果、修改分析参数、退出绘制模式时立即取消，已经落下的多边形保留，未画完的丢弃。取消不弹错误，只在按钮上恢复。
- 完成后 toast：「已自动绘制 N 处掩码（共 M 处，前 K 处；含 H 处孔洞已一并覆盖），可手工调整后再生成掩码」。提示必须说明不是精确边界。

### 6.4 重复点击与撤销

- 重复点击不做追加：每次自动绘制前移除上一次自动批次里仍然存在的多边形，再画新的一批；手绘多边形不受影响。实现上用 diff store 保存上一批 `Poly` 对象引用（`WeakSet` 或数组），按对象身份移除；被用户合并过的对象已经不在列表里，自然跳过。
- 绘制后仍可用现有的单步撤销 / 删除 / 合并；点数多时逐条撤销较慢，是否增加「撤销本次自动绘制」的批量入口，列为待确认项。
- 分析结果被清除或重新分析不会自动删除已画的掩码；掩码是人工资产，清除分析结果不连带清除掩码（与现有「清除结果不影响已加入的掩码」一致）。

## 8. 待确认

1. 边距比例用 0.05（面积比多在 1.1–1.65）是否合适；是否需要给用户一个「紧 / 标准 / 松」三档。
2. 顶点上限 16 / 硬上限 24 是否可接受；是否要求一律 ≤ 12。
3. 单次最多画前 16 处是否够用；是否需要「绘制全部候选项」。
4. 点击后自动进入绘制模式是否可接受；若不希望切换模式，需要另做常显的自动绘制覆盖层。
5. 按钮只在热力显示方式下出现，还是只要结果存在（包括原图标记）就出现。
6. 孔洞区域默认被外接多边形填掉，是否需要在绘制前二次确认、按孔洞占比跳过，或加一项提示。
7. 重复点击按「替换上一批」处理是否合适；是否需要批量撤销入口。
