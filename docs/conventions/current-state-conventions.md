# 当前状态口径规范（sr_agent_platform）

> 日期：2026-10-09 · 状态：已定
>
> **定位**：约束 `docs/` 全部文档与代码注释的**叙述对象**——一律只描述**当前状态**，不得记录任何 AI 历史修改记录，也不得把尚未确认的实现偏差写成新的业务规则。
> **与另两份规范的分工**：[naming-conventions.md](naming-conventions.md) 管文件/目录/标识符**怎么起名**；[terminology-conventions.md](terminology-conventions.md) 管同一个概念**该叫什么词**；本文管写进去的内容是「现状」还是「往事」。
> **适用范围**：`docs/`（含 `docs/status/`）、根目录 `.md`、`backend/`、`frontend/src/`、`.e2e/`、`deploy/` 内的文档与注释。
> **不适用**：git commit message（改动过程归 git 管）；外部导入的引文（见 §5）。

---

## 1. 四条规则

| 编号 | 规则 | 含义 |
|---|---|---|
| R1 | **只写当前状态** | 文档与注释描述此时此刻代码与系统的真实状态。读者读完应能直接照着做，不需要先判断「这条还算数吗」 |
| R2 | **不留 AI 修改记录** | 不写「改了什么、原来是怎样、什么时候改的」。**事实保留，时序与经过去掉**（见 §3） |
| R3 | **不把未确认的偏差写成规则** | 尚未验证的实现差异只能标 **待核**，不得升格为业务规则、字段说明或验收判据。措辞分 **实测 / 推测 / 待核** 三档 |
| R4 | **没有豁免的文档** | 任何文档都不例外，包括刻意保留的「历史档案」「变更登记」「已废止对照表」等体裁——它们全部改为当前状态口径 |

**R1 与 R2 的关系**：两者是一件事的两面。想让读者不误读现状，就不能在现状旁边堆放往事——删掉往事是保证现状可读的手段，不是洁癖。

---

## 2. 禁止写法

| 禁止 | 反例 | 应写成 |
|---|---|---|
| 改动叙述 | 「本次把 X 改为 Y」「原来的 A 已作废」 | 直接陈述 Y：现在字段/规则是什么 |
| 时序副词 | 「目前已改为读 JPG」「不再走 XX 路径」 | 直陈现状：「后端读 JPG」「XX 路径不参与」 |
| 临时规划的过程状态 | 「phase1–phase5」「阶段 1–5 待做」 | 只写已落地的现状；未落地的过程规划不进长期文档 |
| 废弃对照表 | 「已废止 X → 现用 Y」 | 只写现用词 Y |
| 变更登记表 | 「2026-09-04：登记类目 …」 | 现状即为登记结果，过程走 git |
| commit / 日期当佐证 | 「（commit `8c197fc`）」 | 删；确有需要时写实测值本身 |
| 常驻的临时态 | 「待回滚」「临时方案」「先这样」 | 落定即改写为现状；未落定则整段不写 |
| 事故经过叙事 | 「复现全黑 → 定位 alpha → 修改 …」 | 只留结论与当前做法；症状与当前对策的对应关系可写 |
| 存量问题清单 | 「以下 N 处待改」「未收口的都列在下面」 | 改完再写；文档里只留结果 |

## 3. 什么不算历史记录（边界）

去掉的是**时序与经过**，不是**事实**：

| 情形 | 处理 |
|---|---|
| 实测得到的数值（如浏览器单次分配上限约 2GB） | 保留数值与「实测」标注，**去掉日期与复现过程** |
| 领域事实、协议版本、镜像版本 | 本身就是现状，保留 |
| 踩坑结论（症状 → 当前对策） | 保留；「怎么发现的」不写 |
| 第三方引文、外部导入的存档 | 见 §5，不改 |
| 尚未验证的观察 | 保留，但必须标 **待核**，且不得进入规则/判据表述 |

---

## 4. 两个判定示例

**例 1 · 过程规划**：某次开发临时规划了 phase1 到 phase5 五个阶段。任何文档都**不得**出现 phase 相关字段描述；只按代码与项目现状更新文档内容。

**例 2 · 决策取代**：需求 A 的决策是当前项目现状，需求 B 的决策是本次开发的新决策且 A 作废。文档**只记录 B**，不得留下 A 的历史痕迹（不写「A 已作废」「由 A 改为 B」）。

---

## 5. 豁免

以下内容不作替换、不作改写（与 [terminology-conventions.md §2.2](terminology-conventions.md) 一致）：

- `docs/agent-book/**`、`deepseek-harness-master/**`、`frontend/dist/**`、`CloudReview_Update_*/**`。

它们的「历史」是**引文与上游产物本身**，改动等于篡改来源。

---

## 6. 自检

改完文档或注释后跑一遍（`改为`、`原` 一类词有正常义项，命中处必须逐条回读，不得盲替）：

```bash
grep -rn -E "已废止|已作废|已废弃|已中止|已下线|不再使用|原方案|旧版|曾经|早先|本次(改动|修改|开发|任务)|上一轮|变更登记|变更记录|commit [0-9a-f]{7}" \
  --include=*.md --include=*.py --include=*.ts --include=*.vue --include=*.js \
  --exclude-dir=node_modules --exclude-dir=deepseek-harness-master \
  --exclude-dir=agent-book --exclude-dir=dist .
```

---

## 7. 修订

本规范自身的修订走 git commit，头部日期随修订更新（同 [naming-conventions.md §6](naming-conventions.md)）。**不在本文追加修订记录**——那正是 R2 禁止的写法。
