# 项目术语规范（sr_agent_platform）

> 2026-09-28 / 草稿（§2 已执行，§3–§6 待逐条确认）
>
> **定位**：约束文档与代码注释的**用词**，消除同义混用、黑话与自造词，保证读者不必猜词。
> **与 [naming-conventions.md](naming-conventions.md) 的分工**：那份管**文件名/目录名/标识符**怎么起；本文管**正文与注释**里同一个概念该叫什么。
> **适用范围**：`docs/`、`deploy/`、`backend/`、`frontend/src/`、`.e2e/`、根目录 `.md`。

---

## 1. 为什么有这份规范

「烘焙」一词在本仓被高频复用，先后盖住四个不同概念（生成动作 / 产物文件 / 生成规则 / 缩放倍率），并且与 `preview_jpg.py`、`hasPreview`、`GET /api/scenes/{id}/preview` 这套代码侧命名**各说各话**。读者要先做一次词义映射才能读懂链路，这是成本。

由此确立本文的总原则：

| 原则 | 含义 |
|---|---|
| 不造词 | 能用既有汉语词表达的，不自造术语，不用行业隐喻 |
| 不黑话 | 比喻性说法（赢、钉、抢、裸、闸）不进正文与注释 |
| 与代码同词根 | 正文用词优先取自代码既有字段名与路由名，减少映射层 |
| 一名一义 | 同一概念全文一个名字；同一名字不承担两个概念 |
| 分清实测与推测 | 与 `gui-experience.md` 一致：**实测** / **推测** / **待核** 三种措辞分开写 |

## 2. 主词：预览生成（2026-09-28 已执行）

**已废止**：用「烘焙」及其简写「烤」表示服务端把源栅格降采样并拉伸后写出预览 JPEG 这件事。

**现用主词**：「生成预览」。产物称「预览 JPG」，规则称「预览生成规则」，倍率称「缩放档位」。

| 已废止 | 现用 |
|---|---|
| 烘焙 / 服务端烘焙 / 触发烘焙 | 生成预览 / 服务端生成预览 / 触发生成预览 |
| 不烘焙、永不烘焙 | 不生成预览 |
| 重烤 | 重新生成 |
| 急烤（SR 产物转 COMPLETED 后主动生成） | 产物完成后主动生成 |
| 惰性烤、懒烘焙 | 惰性生成（首次访问时生成） |
| 烘焙 JPG、烘焙产物 | 预览 JPG |
| 烘焙规则 v3 | 预览生成规则 v3 |
| 烘焙档位 | 缩放档位（÷2…÷32） |
| 掩码烘焙（`POST /api/masks`） | 掩码生成 |

**为什么是「生成预览」**：代码侧本来就叫 preview —— `hasPreview`、`jpgUrl`、`previewDiv`、`GET /api/scenes/{id}/preview`、`services/preview_jpg.py`、`<stem>_preview.jpg`。词根回到 preview 之后，正文与代码不再各说各话。

**为什么不用另外三个**：

- **预生成** —— 不准确。预览是惰性生成的（首次打开才生成），不是提前备好的；且盘阵里本来就存在预生成的 `.jpg` 显示件，用「预生成」会与「服务端生成的那份」正面撞车，恰好抹掉最重要的区分。
- **渲染** —— 与前端 canvas 绘制撞词。
- **导出** —— 暗示用户主动下载，实际是后端自动落盘。

### 2.1 单字「烤」的处理

「烤」是**动词词干**，粘着补语（烤完 / 烤成 / 烤出来 / 烤到盘上 / 没烤过），不存在单一对译词，**禁止对「烤」做批量替换**，必须逐条看句子。短形用「生成」——与主词同根，语法位和「烤」对齐（烤了→生成了、烤过→生成过、没烤过→没生成过）。

| 粘着形式 | 替换 |
|---|---|
| 只烤 X / 烤一份 / 烤两张 | 只生成 X / 生成一份 / 生成两张 |
| 不烤 / 永不烤 / 从不烤 | 不生成 / 永不生成 |
| 没烤过 / 从没烤过 | 没生成过 |
| 烤完 | 生成完 |
| 烤到盘上 / 烤进目录 | 生成到盘上 / 落盘 |
| 烤出来 / 烤出的 | 生成的（「烤出来那份」→「生成的那份」） |
| 刚烤的 / 已烤好的 | 刚生成的 / 已生成的 |
| 首烤 / 漏烤 | 首次生成 / 漏生成 |
| 预烤（仅「从不预烤输入影像」一类） | 预生成 —— 此处「预」指提前，是准确的 |

**「生成」套不进去、必须改写句子的**：

| 原文 | 不要写成 | 改写为 |
|---|---|---|
| 把 2.4 万像素级的源**烤成** 1.5 亿像素 | 生成成 | 把…**降采样到** 1.5 亿像素 |
| **没烤成** | 没生成成 | **没生成成功** |
| 删了又被**烤回来** | —— | **被重新生成** / **被写回** |
| **烤不动** | —— | **生成不了** |
| **白烤**一张图 | —— | **无效生成**一张图 |

### 2.2 替换执行顺序与雷区

顺序（按词长降序，避免误伤）：

1. 长词：「烘焙规则」「烘焙档位」「掩码烘焙」「服务端已烘焙」「服务端烘焙」「烘焙产物」「烘焙 JPG」「触发烘焙」。
2. 简写：「重烤」「急烤」「惰性烤」「首烤」「漏烤」。
3. 粘着形式：见 §2.1 表。
4. **最后**才是裸「烘焙」与裸「烤」，且必须逐条回读。

**两轮替换的已知副作用**：当原文中「烘焙」紧邻「预览」二字（`烘焙预览`、`预览烘焙`）时，第二轮替换必出叠词。执行后收尾 grep：

```bash
grep -rn "生成预览预览\|预览生成预览\|生成生成" \
  --include=*.md --include=*.py --include=*.ts --include=*.vue --include=*.js \
  --exclude-dir=node_modules --exclude-dir=deepseek-harness-master \
  --exclude-dir=agent-book --exclude-dir=dist .
```

**禁止替换的目录**：

- `docs/agent-book/**` —— 转录的第三方书，「烘焙进下游状态/权重」是原文，改等于篡改引文。
- `deepseek-harness-master/**` —— vendored 上游仓库。
- `frontend/dist/**` —— 构建产物，改了下次 build 即失效。
- `CloudReview_Update_*/**` —— 外部导入的参考代码，只读存档。

## 4. 术语误用（待确认）

- **真值**（21 处）——「真值」是 ground truth 的规范译名，用于 `backend/api/app.py` 的「hasPreview 一律填真值」、`backend/tests/test_scene_resolve.py` 等处时，实际语义是「以缓存实际状态为准」「基准值」。测试语境规范词为**预期值 / 基准**。建议替换。
- **档位**（395 处）—— 隐喻可接受，但**首次出现**应写全「缩放档位（÷2…÷32）」，后文方可简称。

## 6. 保留不动（本仓领域词与规范词）

- **盘阵** —— 用户侧领域词，指 `/DiskArray`。
- **超分 / SR / NOSR / 掩码** —— 领域规范用法或已进入生产件命名。
- **掩膜中心点坐标.txt** —— 盘上真实文件名。
- **时间戳、幂等、惰性、屏障、缓存命中、降采样、直方图均衡、规则签名** —— 规范术语。
- **如实 / 不谎称** —— 本仓刻意的措辞纪律（状态如实上报），不是黑话，保留并鼓励。
