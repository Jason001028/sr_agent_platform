# 生产场景命名规则与目录层级（盘阵 GSHC2IMPS）

> 用途：平台按「文件名 → 场景目录」反推盘阵路径（查看器拖入本地影像时）所依赖的规则。
> 规则 = 用户口述的生产命名规范 + 一次真机路径核对；实现见
> [backend/pathguard.py](../../backend/pathguard.py) 的 `scene_name_layers` /
> `infer_scene_paths`，唯一真源在那里，前端不自拼路径。

## 一、目录层级

生产数据在 `/DiskArray/GSHC2IMPS/PRODUCT` 之下，**六层**：

```
<根>/GSHC2IMPS/PRODUCT/<年>/<月>/<日>/<卫星型号>/<段级目录>/<景级目录>
```

实测（node81-135）—— 同一景的两层目录名：

```
/DiskArray/GSHC2IMPS/PRODUCT/2026/09/02/JL1KF02B03/
  JL1KF02B03_PMS09_20260902120156_200535158_102_001_L1_PAN/        ← 段级
    JL1KF02B03_PMS09_20260902120156_200535158_102_0025_001_L1_PAN/ ← 景级（场景目录）
```

`<年>/<月>/<日>` 取成像时刻那 14 位字段的前 8 位。用户侧看到的是同一份数据的
Windows 形态 `W:\GSHC2IMPS\PRODUCT\...`（`W:` 由 `SR_DRIVE_MAP` 映射到盘阵根，
默认 `W:=/DiskArray`）。

平台要打开的是**景级目录**：它下面有 `<目录名>.tif`（SC）或 `PAN.tif`（RC），
以及 `<目录名>_meta.xml`。

`<目录名>_meta.xml` 的前缀是**整个目录名**，也就是**完整生产名**（含 14 位成像时刻）
—— 用户口径：「`_meta.xml` 前一般是完整前缀」。所以只有目录名本身就是生产名时，
这个文件才可能存在；日期目录（`…/PRODUCT/2026/09/18`）、卫星型号层、段级目录里都
不可能有它。**粘场景目录时必须粘到景级这一层**（比日期目录深三层）；粘错层时平台按层
报「还差几层 / 差哪一层」，见 [api-contract.md](../planning/api-contract.md) 的 404 一段，
措辞实现见 `backend/api/app.py::_why_not_scene_dir`。

## 二、名字分段

以 `JXGF07D03_PMS_20260622052600_200516571_101_0006_001_L1_MSS` 为例（下划线分段）：

| 序号 | 值 | 含义 |
|---|---|---|
| 0 | `JXGF07D03` | 卫星型号 |
| 1 | `PMS` | 传感器（PMS = 全色多光谱相机，全色与多光谱两种产品都有） |
| 2 | `20260622052600` | 北京时间成像时刻（14 位） |
| 3 | `200516571` | 任务计划号（9 位） |
| 4 | `101` | 段号（3 位：第 1 位是通道号，后 2 位是段序号） |
| 5 | `0006` | 景号（4 位） |
| 6 | `001` | 生产次数（预处理系统的生产次数） |
| 7 | `L1` | 处理级别 |
| 8 | `MSS` | 产品（`MSS` 多光谱 / `PAN` 全色） |

## 三、由文件名反推目录

- `<卫星型号>` = 第 0 段。
- `<段级目录>` = 景级名字**去掉第 5 段（景号）**后的名字。实测对照：
  景级 `..._102_0025_001_L1_PAN` ↔ 段级 `..._102_001_L1_PAN`。
- 形态判据（不满足就不生成这条候选，**不硬拼空段**）：名字至少 7 段，且第 4 段是
  3 位数字、第 5 段是 4 位数字。
- 用户拖进来的文件名**可能带光栅后缀**（`.tif/.tiff/.img/.jpg/.jpeg`），拼路径前先剥掉
  —— 目录名从不带后缀。
- 拖进来的若是 **`.jpg`**（盘阵上那份显示件），身份判据是**名字 == 场景目录名**（生产全名），
  不是栅格输入的 stem：纯 RC 场景里输入叫 `PAN.tif`，显示件却叫 `<目录名>.jpg`，拿它去比
  `PAN` 永远比不过（见 [api-contract](../planning/api-contract.md) §3.5）。
- 各段的分隔符**下划线与空格都认**，段级目录名按**原文的分隔符**重建
  —— 拿空格名拼出下划线的段级目录必然 stat 不到。盘阵上的真形态是下划线（第一节那组
  实测样本），空格形态只在用户口径里出现过，属**防御性**支持。
- 日期取名字里第一个 14 位（取前 8 位）或 8 位数字段，两者都取不到就报错让用户手粘目录。
- **日期目录要试两天：名字里的成像日，以及它的次日**。名字里的 14 位是
  **成像**时刻，而盘阵按**生产日**建目录 —— 夜里成像的景记在第二天，`…_20260917124710_…`
  大多躺在 `2026/09/18/` 下。候选顺序 = 成像日在前、次日在后，两天都在就命中成像日。
- **《待修复清单》第一列约定俗成省掉第 8 段（产品）**（用户口径）。质检部门给的
  `.txt` 第一列写 `…_101_0020_001_L1`，盘阵上的景级目录却是 `…_101_0020_001_L1_PAN`，
  而同一行的描述列里写着「影像类型:pan」。**这一列是唯一能补出产品段的线索**，所以反推时
  由调用方把它一并递下来（`POST /api/scenes/resolve` 的 `product` 字段，见
  [api-contract](../planning/api-contract.md) §3.5）。产品段是**生产名的最后一段**，而按名字
  反推的两级目录名都拿它拼（景级 = 名字本身、段级 = 去掉景号那一段），少一段就**两级一起错**
  —— 表现为整批图 404「目录不存在」，名字看着却像是对的。补法是**把产品段追加到名字后面**
  再走本节的规则，段级名因此自动跟着对；补哪一段不写明时按 `_PAN` 处理。

## 四、已知边界与待核

- 「段级 = 景级去景号」这条关系目前只有**一组真机样本**支撑（第一节那组）。其它卫星、
  其它产品是否同样成立**待核**：`ls /DiskArray/GSHC2IMPS/PRODUCT/<年>/<月>/<日>/<卫星型号>/`
  一眼可见。规则若在某些产品上不成立，表现为反推落空并报出候选 —— 不会静默指错目录。
- 反推**只认六段生产树**。平铺部署（`<日>/<景级目录>` 直接相邻）不能被**名字**打开，
  只能粘目录路径 —— 而 `flat_scene_layout` 仍按层数认出这种拓扑，报错措辞不会指错层。
- 反推不到时的既定行为：**报错并列出试过哪些候选、各自为什么不行**，由用户把场景目录粘进
  「盘阵场景」栏打开，绝不静默换一条路径提交。
- **待核**：盘阵上到底有没有空格分隔的生产名。真机 `ls` 一个日期目录即可确认；若确认没有，
  `pathguard._FIELD_SEP_RE` 的空格那一半可以删掉（不删也无副作用，判不合规则时只是多拼
  一条 stat 不到的候选）。
- **产品段那条规则现有两份实现**，这是**故意**的、也是本文件唯一一处「同一条口径两处写」：
  - 真源（**唯一**参与拼路径的那份）：`backend/pathguard.py::scene_name_products` ——
    「原样恒第一 + 按影像类型补产品段」，补出来的名字随后由后端按固定候选 `is_file()`。
  - 镜像（**只用于匹配**）：`frontend/src/lib/qcbatch.ts::sceneNameCandidates` —— 把《待修复
    清单》第一列的行名，对上左侧卡片的场景目录名（`matchesScene`：目录末段 ∈ 候选集合）。
    联动必须瞬时，不能「点一行就发一次 resolve 去问」。
  两处**不能合并**（前端不 stat、后端不碰 DOM），所以靠两条金丝雀防静默漂：后端
  `backend/tests/test_paths.py::TestSceneNameProducts::test_product_codes_mirror` 与前端
  `frontend/src/lib/__tests__/qcbatch.test.ts` 各钉一次 `('PAN','MSS')` 这个字面量。改了
  产品段口径却只改一头 → **两条同时红**，这正是要的效果。
  镜像**永不参与拼路径**：它的产物只进「相等比较」，落后于真源的最坏结果是「点了行没亮卡」，
  绝不会让平台去打开一条自己拼出来的路径。
