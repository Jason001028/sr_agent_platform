# 交替对比（Flicker Comparison，2026-11-03）

顶部「图像对比」新增第四种模式：在同一块画布、同一视口里，按固定节拍在两张**同一景**的影像
之间硬切换可见图层，用来分辨超分前后的细节差异。入口与点选 / 分屏对比并排，进入后操作收在
画布顶部的悬浮胶囊里，不占常驻工具栏。

## 1. 入口与胶囊

- `CompareBar.vue` 四选一：`关闭 / 点选对比 / 分屏对比 / 交替对比`；工具栏那颗对比键的短标签
  在交替模式下显示「交替」。
- 进入后画布顶部居中浮出胶囊（`FlickerControls.vue`），顺序固定：
  `交替对比 | PAN/NOSR | 1.0秒 | 播放/暂停`。
  - 配对两端是短标签（`stageLabel`，没有就用文件名去扩展名）；**当前可见的那张加粗高亮**，
    每翻一面高亮跟着换。
  - 节拍下拉五档：`0.6 / 0.8 / 1.0 / 1.2 / 1.5 秒`，选值存 localStorage
    `sr.viewer.flickerInterval`，脏值回落到 1.0 秒。
  - 播放键只在**用户点**时才开跑；暂停停在当前这一帧，不回第一张。
  - 不能播放时按钮置灰，胶囊下方给一句具体原因（缺第二张 / 配准不通过 / 像素还在加载）。
- 胶囊自身 `mousedown / dblclick / wheel` 全部 `.stop`，点它不会平移画布或触发缩放。
- 进入交替时右侧「上下文侧舱」保持原状态：从分屏进来时它仍是收起的，退出到单屏再还原，
  避免中途展开改变画布宽度、导致刚接过来的视口跳一下。

## 2. 配对与配准

判据都在 `frontend/src/lib/flicker.ts`，store 只负责选人：

- **从分屏进入**：直接沿用分屏里摆好的那两张，不自作主张换图。
- **从单屏进入**：以当前活动图为参考图，在**同一场景目录**（`sceneDir`，缺省退 `lqPath`）
  的其它 rec 里挑：
  1. 先按能否通过配准排序；
  2. 再按环节互补排序（看本体优先 NOSR；看产物优先 NOSR；看 NOSR 优先产物）；
  3. 同分取 id 小的，保证列表重排不影响选择。
  占位卡（`pending`）、自己、别的场景目录一律不参与。

**配准口径**（`registrationRefusal`）：

- 两张尺寸都已知；
- 两张有同一个非空场景目录；
- 宽高比相对偏差 ≤ 1%（`FLICKER_ASPECT_TOLERANCE`）—— 整幅图按归一化坐标一一对应，
  宽高比一致时这条映射不变形地覆盖同一片地面；2 倍产物比例不变，被裁过的图会露馅。
  判据按**比例**计算（`aspectDeviation`），不要求像素网格严格成整数倍：PAN 本体与
  NOSR 常是不同分辨率（生产实测 SC 本体/NOSR ≈ 1.96），重采样取整后
  `宽1×高2 ≠ 宽2×高1`，但覆盖比例一致，仍可交替。预览缩略图各自取整的偏差同样按
  这 1% 放行，不再要求缩略图乘积严格相等。

任何一条不满足就**禁止自动交替**并说明原因，不拿两张不同地面的图来回闪。

## 3. 播放循环与停止条件

计时器只有一个（`stores/viewer.ts` 的 `scheduleFlickerTick`，`setTimeout` 串行续拍）：

- 每拍只翻转 `flickerIndex`、清掉上一张的红叉标记、`renderTick++`；不调 `activate`、
  不重新解码、不重建 Canvas。
- **自动暂停**（`noteUserIntent`）：平移、缩放、切图、切侧、改分隔、进入掩码 / ROI 编辑、
  双击复位、像素定位都会先停播，画面停在用户此刻看到的那一帧。
- **页面隐藏**：`ViewerPage.vue` 在 `visibilitychange` 且 `document.hidden` 时调
  `flickerPause()`；计时回调里还会再查一次 `document.hidden` 兜底。
- **组件卸载**：页面卸载时 `flickerStop()`（清计时器 + 停播）。
- **配对失效**：参与的两条 rec 被关掉，或活动图换了，watch 会停播并重新配对；活动图换了
  就以新活动图为参考图重配。
- **减少动态效果**：`startFlicker` 在 `prefers-reduced-motion: reduce` 下拒绝启动并 toast 说明
  （可以手动查看两张图）；计时回调里同样会停。最短档 0.6 秒，不做更高频的闪烁。

## 4. 视口与图层

- 两张图共用一份 `flickerView`（参考图的视图）。第二张的显示视图是
  `remapViewForImage(flickerView, a.thumb, b.thumb, 画布宽高)` 的纯换算结果 —— 同一块地面、
  同一个视中心、同一个显示比例。
- 在第二张上滚轮 / 拖动 / 小地图导航，写回 `view` setter 时会**反向换算回参考图**，
  两张图不会各自漂移。
- 渲染层只换 `panes[0].rec` 与显示视图；缩略图 / 预览 JPG / 拉伸模式全部复用既有缓存。
  进入模式时 `prepareFlickerPixels()` 只为**还没有像素**的懒卡补一次 `loadCardPixels`。
- 预览内存淘汰把配对的两条 id 当「在屏」保护，不会在交替中途把另一张淘汰掉。
- 叠加层（ROI / 掩码 / 检测框）属于参考图，翻到第二张时 `TifCanvas.renderDraw` 提前返回；
  进入绘制的动作本身会先暂停并回到第一张。状态栏与光标坐标读 `displayRec`
  （交替时是当前可见图），掩码 / ROI / Agent 仍只认 `activeRec`。

## 5. 退出与状态恢复

- 交替期间**不写 `viewA` / `viewB`**，所以「切回原模式恢复原始查看状态」由「根本没改」保证。
- 从单屏进入、期间没切图：退出后单屏视口一个数都不变。
- 从分屏进入：`viewA/viewB` 存的是半幅视口，退出时重新 `fit()` 成整幅。
- 期间切过图：退出后把交替中看到的视口交给单屏（`viewA`），并显示切过去的那张本体。
- 退出即清计时器、配对与帧号，胶囊随 `<Transition>`（`--motion-fade`）淡出。

## 6. 动效

- **影像翻面是硬切，不做淡入淡出** —— 淡变会让细节差异互相叠加，失去交替对比的意义。
- 胶囊出现 / 消失、名字高亮、按钮底色只用 `style.css` 的 `--motion-*` / `--ease-*` 令牌，
  `prefers-reduced-motion` 下这些过渡由既有全局规则收掉。

## 7. 修改边界

未改影像坐标转换、SR 结果验证、分屏对比、Agent 状态机；`CompareMode` 只增了一个合法值。
`viewer/e2eHooks.ts` 补了 `flicker()`、`flickerPlay()`、`flickerPause()`、`flickerToggle()`、
`setFlickerInterval()` 五个观测 / 驱动钩子。

## 9. 未覆盖 / 待核

- 真实盘阵大图的体感（翻面是否跟手、内存是否稳定）未在真机验；e2e 用两张 400×200 合成 JPG，
  只验模式与状态机。合成图默认走直方图均衡会把两个灰阶压到一起，脚本内先切线性拉伸再采样，
  验的是「翻面」，与拉伸策略无关。
- 分屏 A/B 宽高比略有差异时仍可进分屏；交替会在胶囊下说明为什么不能自动交替，
  需要用户换同比例的那张。
- 页面隐藏 / 减少动态效果由计时回调与启动检查共同兜底，未单独做系统级 e2e（需要模拟
  `prefers-reduced-motion` 与页面生命周期）。
