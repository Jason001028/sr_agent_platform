# 自动巡览（2026-11-04）

工具栏下采样右侧无人机图标只打开设置，用户显式开始后才驱动现有 `setPaneView`。第一版仅允许单景、非对比、非编辑状态，不读取真实生产影像，不新建解码或预取链路。

## 文件与状态

- `lib/autoTour.ts`：原图像素空间蛇形网格规划、85% 视野步长上限、边界裁剪、匀速段及端点加减速。
- `stores/autoTour.ts`：idle / playing / paused，rAF 时间差驱动，控制现有 Camera；缩放不超过预览 1:1。路线最多 4096 点，超限说明原因，不能形成路线也说明原因。
- `AutoTourButton.vue` / `AutoTourControls.vue`：设置、范围、三档速度、循环、播放控制、页面隐藏与 reduced-motion 监听。退出 Viewer 后停止并清理临时状态。
- `MiniNavigator.vue`：仅绘制同一条实际路线与当前位置，保留视口映射和用户收起选择。
- Viewer 仅额外暴露已有 `stopViewAnim`，不重写渲染或坐标算法。

初始定位 1000ms；速度 70 / 110 / 160 屏幕 px/s；每段两端各约 300ms 加减速，短段相应缩短，节点停留 300ms；循环到端点后反向连续返程。控制胶囊沿用 200ms motion token；Hover 150ms。长帧最多消费 100ms，避免卡顿后瞬间大跳，因此严重掉帧时实际速度会降低。

手动 Camera 操作、用户意图事件、编辑会暂停。暂停按钮和后台隐藏不重置路段进度；手动接管后主动继续会先平滑返回暂停时的路线位置，再继续前进。切景、改变预览、窗口大小或切换对比后清空不再适用的路线，保留暂停说明，要求重新规划。没有自动恢复和停止时的强制归位。

## 验证

初版前端 686 项测试通过，typecheck、build 通过。既有 vendor sourcemap 缺失和大 bundle 警告仍存在。

`.e2e/test-auto-tour.js` 用合成 2400×1600 预览和 Mock API 验证入口不移动、启动运动、暂停视野稳定、继续、手动缩放接管、隐藏与恢复、Resize、掩码编辑、分屏切换、Esc、reduced-motion、页面卸载和页面异常。浏览器截图为 `.e2e/artifacts/submission-feedback/auto-tour.png`，已人工检查。

纯函数测试覆盖比例、真实像素边界、85% 步长、可见范围裁剪、小图拒绝、极端长宽比及匀速段。循环反向逻辑已实现，但完整长路线循环、实机大影像帧率与多尺寸完整视觉回归尚未专项验收。巡览仅辅助浏览，完成仅提示「巡览结束」，不代表检测或质量验收。

## 双图交替巡览及配对诊断（2026-11-05）

328px 面板支持交替开关、影像配对、驻停/移动模式、0.6/1.0/1.5 秒间隔，以及 20/35/50px/s 双图巡览速度。配对载入后可先手动切换核对；切换复用预览缓存和共享 Camera，不重复 Fit 或 TIFF 解码。驻停模式到点后等待 300ms，再交替两轮；移动模式运动中持续切换。统一暂停、继续、结束及手动接管；隐藏暂停，切景与卸载使待完成的配对请求失效。

鹰眼分别记录两张图实际绘制后的覆盖，以 128×128 布尔栅格的交集生成 22% 青绿色遮罩，重复覆盖不叠深。结束后保留本景足迹，切景/换预览/换配对清除。

### 候选与校验分开

`GET /api/scenes/{id}/siblings?tour=true` 返回 `tourItems` 与 `tourDiagnostics`。普通 siblings 请求不增加巡览探测。候选包括 Scene 本体与已识别输入、NOSR、ori、old/old_latest/old_2；old 是独立角色，不冒充 ori。前端可传最多 32 个已打开且同景的 Scene ID，后端复核路径白名单、同目录和生产环节身份；不扫描目录，不跨景配对。

下拉框列出所有已识别的配对候选。证据不足的条目禁用，并显示具体原因；一个有效组合自动选中，多组合须手选；重开面板保留仍有效的选择。旧后端缺少 `tourItems` 时明确提示前后端同包更新。

可用配对仍要求同生产序列、明确角色、有效源版本、等比例像素网格，以及共同的可靠配准证据。当前证据读取支持北向上的 GeoTIFF EPSG/PixelIsArea/单锚点；范围和方向必须完全一致。预览取整导致两图比例不一致也拒绝，避免共享等比 Camera 的垂直漂移。载入预览后再次复核源版本和证据，全部就绪才切换 pair。

### 原生产数据限制（已由下方“取消 GeoTIFF 必需门槛”调整）

生产 `SR_code/util.py::writeTiff()` 仅创建 TIFF、写入像素，没有设置地理变换或投影。因此同目录中已关联的 NOSR、old、完整生产名 PAN，仍可能缺少 GeoTIFF 配准证据。原实现把这些候选直接过滤，造成空下拉框；现改为显示候选和缺失原因。

本轮没有把“同目录/同尺寸”升级为配准证据，没有伪造 CRS 或归一化空间范围。缺少可验证证据的生产影像仍不能启动自动交替巡览；需要另行接入绑定实际源版本的生产映射/配准记录。新 Manifest 上的 `tourIdentity` 也只保留实际读取到的证据，不因清单尺寸关系而自动通过。

### 紧凑面板与路线选择（2026-11-05）

启动面板保留 328px 宽度，采用三张 SVG 路线卡、双列参数、紧凑开关与单条配对诊断；面板右对齐入口并约束在视口内。新增纵向往返、向内环绕，横向往返仍为默认，默认规划坐标与顺序保持一致。示意卡与实际规划器复用 `tourGridOrder`，运行或暂停时锁定路线选择，结束后可重新选择。此处为预设路线选择，不提供任意自由绘线编辑。

鹰眼不透明度改为对影像、底板、边框和阴影统一合成后应用一次透明度，支持 0–100%；设置与收起按钮保持可用。0% 浏览器截图像素与隐藏鹰眼后的区域一致，避免浅色底板残留。

验证：前端 724 项测试、typecheck、build；合成影像浏览器覆盖三种路线、键盘选择、1280/1366/1600 宽度布局、双图驻停/移动交替、鹰眼 0/50/100% 与窗口控制。截图分别位于 `.e2e/artifacts/tour-panel-routes/`、`.e2e/artifacts/minimap-opacity/`，未覆盖此前验收图。

### 取消 GeoTIFF 必需门槛（2026-11-05）

按用户要求，GeoTIFF 全幅配准标签不再是配对前提。同生产序列且角色明确的 PAN ↔ NOSR / ori / old，可以按全幅归一化像素坐标进行共享视口比较；缺少一张或两张图的 GeoTIFF 标签均不阻止选择和运行，也不显示缺失标签的拒绝提示。多候选仍由用户手选。

保留源版本、有效尺寸、源图与预览宽高比检查；若两图均提供空间映射而范围或方向明确冲突，仍拒绝该组合。此策略使用生产关联及等比例全幅关系，不代表完成了影像内容自动配准。

回归包含无 GeoTIFF 标签的候选选择、载入、缓存手动切换、驻停两轮、移动交替和鹰眼交集；专项测试也保留异序列、源版本失效、比例不符与明确空间冲突的拒绝行为。
