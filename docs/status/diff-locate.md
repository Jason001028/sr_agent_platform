# 智能差异定位（2026-11-05）

顶栏自动巡览右侧新增「差异定位」入口，用传统 CV 比较两张遥感影像，输出连续差异图与成片连通区域。第一版只读，不新增解码链路：分析输入是查看器已加载的预览像素，经统一网格与统一灰度映射后送到后端。

## 链路

- `lib/diffLocate.ts`：公共分析网格（长边上限 2048）、双线性采样、无效值（NoData）排除、共享灰度范围、分析网格与缩略图/原始像素的双向坐标映射。
- `stores/diff.ts`：配对建议、视野裁剪、灰度 PNG 上传、结果与图层状态、候选定位/悬停、显式加入掩码、交替对比入口、原始 ROI 精算与返回预览。
- `backend/services/image_diff.py` + `POST /api/diff/analyze`：像素差分与 SSIM 两条管线共用归一化、形态学、连通域、面积过滤与排序，返回 `method / imageA / imageB / analysisGrid / differenceMap / binaryMask / regions / parameters`。
- `DiffLocateButton.vue`：336px 面板；`DiffOverlay.vue`：编号标记、悬停、选中轮廓与信息卡；`DiffCandidatesPanel.vue`：侧舱候选清单。

## 口径

- 两张图必须落到同一分析网格，灰度用同一组范围拉伸，禁止各自自动拉伸后相减。共同范围**只统计两图都有效的像素**：某张图在非共同有效区的极端灰度不得撑开量化范围，否则共同区内的真实差异会被压成同一个 8-bit 值而漏检。分位抽样按「从当前采样点向后找最近的共同有效像素」推进，稀疏有效区不会被固定步长整段跳过；只有确认共同有效区为空时才返回无数据，前端直接报错而不是用 `[0,1]` 继续量化。预览显示件本身逐图做过直方图均衡，因此预览结果只代表显示层差异，不能据此判断真实亮度变化。
- 像素差分保留连续 `D_abs ∈ [0,1]` 供热力图；二值掩码经 3×3 开运算、3×3/5×5 闭运算与最小面积过滤，不做过度膨胀。
- SSIM 从局部相似度图取 `1 - S`，与像素差分共用后处理，阈值预设各自独立。
- 热力图与羽化只影响显示：精确二值掩码 `binaryMask` 不变，羽化不参与面积、连通域与后续修复掩码；切换羽化立即重建显示层。
- 结果明确标注「预览分析」或「原始 ROI 分析」，不把预览 JPEG 差分说成原始 DN 差分。
- 检测结果不自动认定为伪影，不自动提交 SR；加入掩码必须用户显式点击，分析候选与人工批注分开保存。
- 分析不依赖自动巡览，可独立使用；两图对比复用现有交替对比与共享 Camera。

## 身份与坐标约束（2026-11-05 复审后）

- 分析/精算发请求前冻结配对、参数与**像素代次**签名（记录是否存在、`srcRev`、加载 `token`、采样尺寸）；响应返回及图层解码后各复核一次，过期响应直接丢弃，不会签成当前结果。换档位/重载开始时 `token` 立即递增，旧结果立刻失效。分析期间配对、方法、灵敏度等控件禁用。
- 结果与显示图层在解码完成后**一次性发布**：先在局部解完热力图与二值掩码，复核请求序号、参数与像素身份均未变，才同时安装；解码期间失效则结果、热力图、掩码都不装，并提示「已丢弃」。
- 候选操作绑定 `result.imageA/imageB.id` 与产生结果时的像素代次，不跟当前配对走；结果过期时禁止加入掩码与精算。定位只驱动显示结果影像的格子，不在任何格子时先激活该影像，不会移动无关影像的 Camera。
- 轮廓由 Moore-Neighbor 外边界追踪得到，不再用外接矩形兜底；闭合多边形按离首点最远的顶点拆成两条开放折线做 RDP，点数超限时逐步放宽容差，再用 4× 亚像素栅格化核对轮廓与连通域掩码的 IoU。区域含孔洞时 `contourKind='outer'`，简化后 IoU 不达标时标 `approx`，两者都与 `bbox` 一样禁止直接写掩码。
- 形态学、连通域、轮廓、重采样与平滑固定走 SciPy，OpenCV 不参与，避免不同机器给出不同面积/坐标；SSIM 优先 scikit-image，缺省时用 SciPy 等效实现并在 `parameters.backend` 标注。
- 原始 TIFF 读取会解析 GDAL_NODATA：有限哨兵做值比较，`nan`/`inf` 哨兵只用 `isfinite` 排除，不会把整块 ROI 判无效；分位数拉伸与 SSIM 只用有效像素；平滑按有效邻域归一化。
- `SampleFormat` / `BitsPerSample` 同时支持标量与数组写法，各波段必须一致；原始 ROI 精算**只接受单波段 TIFF**，多波段输入明确拒绝，不猜「第一波段还是灰度合成」。
- 分辨率不同时按有效权重重采样：无效像素先清零再插值，权重图同步插值，任一插值邻点无效则输出判无效 —— 有限哨兵不会混进有效灰度。原始 ROI 返回**实际夹紧后**的 `sourceRoi` 与 `origin`，区域坐标是 ROI 局部坐标。
- 只传 `sceneId` 的默认分析路径先按两张预览规划受限共同网格（长边 ≤ 分析上限、宽高比相差 >2% 直接拒绝），再把灰度与有效性一起采样过去；不会先按整幅重采样再拒绝。
- `/api/diff/analyze` 的同步计算放到工作线程，不阻塞事件循环。

## 2026-11-06：放宽分析配对门槛

旧提示“精确分析暂不可用：缺少可信配对证据”来自 `precisePairReason` 对 `tourIdentity` 的硬性要求，通常是打开链路未携带巡览身份，不代表两图不能计算差异。差异分析现独立使用 `analysisPairReason`：已打开、尺寸有效、全幅宽高比兼容的两图即可分析，不要求场景 ID、GeoTIFF 或巡览证书。PAN/NOSR 不同分辨率和非整数缩放按现有共同网格重采样；未验证配准只给说明，并随结果保留在 warnings 中。

同一可信场景目录的影像，缺少巡览身份时也允许按比例同步与交替；不再要求两张预览缩略图的宽高比乘积精确相等。自动巡览的服务端候选身份机制继续沿用原链路。明显不兼容宽高比、同一张图、无效尺寸、已知不同坐标系/覆盖范围/方向仍返回具体原因。预览差异不自动成为修复结论或掩码。

验证：新增无证书 4 倍 PAN/NOSR、尺寸取整、无效网格及同景同步专项；差异 Store 实际分析请求也覆盖无证书与不同分辨率。前端全量 65 files / 813 passed，typecheck、build 和 test-diff-visualization.js 通过。

## 2026-11-06：延续到下一景

单图显示热力结果时，工具栏「差异定位」右侧出现半透明的「延续到下一景」。外观沿用鹰眼导航的工具键：28px 高、圆角 8、`--tb-*` 令牌与浅阴影，默认不透明度 0.45，悬停或键盘聚焦时恢复 1。它只在结果存在、显示方式为独立热力图或热力叠加、查看器是单图，且左侧列表还有下一景时出现。

- **下一景** = 左侧列表按场景目录分组后的下一组。分组顺序取卡片首次入列顺序，一键解析按清单行序入列，所以就是清单里的下一景；收藏置顶不影响该顺序，末景不循环。
- **沿用 A/B 角色**：按当前两张图的环节与名字认出 PAN / PAN_old / NOSR / SR / old / ori / 本体，在下一景里找回同角色的两张图。A=PAN、B=NOSR 的组合换景后仍是 A=PAN、B=NOSR，不会反过来；角色对不上时只按共同网格兼容性补位。
- 下一景只打开了本体时，先向只读 `/api/scenes/{id}/siblings?tour=true` 补建缺失角色的身份卡，再按需取像素；仍凑不出兼容的一对就保持当前景并说明原因，不硬切。
- **沿用显示参数**：显示方式、叠加不透明度、羽化、方法、灵敏度、最小面积与高级参数都在 store 里原样保留，点击后直接调用 `analyze()`。切景期间抑制活动景 watcher 的 `ensurePair`，避免刚按角色落好的组合被推荐配对覆盖；切景与补候选期间重复点击直接忽略，分析阶段由 `busy` 挡住。

验证：`diffStore.test.ts` 新增四项（出现条件、角色延续且不被推荐配对覆盖、只读同景候选补齐缺失角色、末景与凑不出配对时的拒绝）；前端全量 66 files / 822 passed，typecheck 与 build 通过。浏览器 `node .e2e/test-diff-continue.js`（先构建）用两景合成影像验证按钮紧邻「差异定位」、28px 半透明与悬停不透明、点击后活动卡切到下一景、A/B 角色保持、显示参数保持且只重新分析一次；截图 `.e2e/artifacts/diff-continue-button.png`、`.e2e/artifacts/diff-continue-next.png`。真实盘阵多景列表仍待内网验收。

## 2026-11-06：亮度归因权重（可选，默认关闭）

差异定位设置面板新增「候选复核 → 亮度归因权重（非线性）」。关闭时行为与之前完全一致；开启后候选按复核权重重排，选中轮廓按权重在冷灰蓝与暖橙之间连续插值，候选行出现一条权重条与灰度 / 中间调 / 平坦度 / 变化量。

判据是连续的，不做「120 是伪影、119 不是」的硬分类：

- 中间调、暗部、平坦度、提亮量都用 smoothstep 隶属度，过渡区为 90–120 / 180–210（中间调）、70–110（暗部）、2–8（3×3 局部标准差）、2–15（灰度差）。
- `w_mid = 1 + 0.8 · M · (0.5 + 0.5F)`，`w_dark = 1 − 0.7 · D · m_bright(Δ)`，`w = w_mid · w_dark ∈ [0.3, 1.8]`；排序分为 `rankScore × w`。
- 原始侧取 A，变化方向取 `Δ = mean(B) − mean(A)`：暗部提亮降权，中间调越平坦升权；暗部变暗不享受折扣。

口径与边界：

- 统计在前端分析完成时附在区域上。预览分析用裁剪后的分析网格与二值掩码；原始 ROI 精算把区域坐标换到缩略图，再从两图各自的预览缓冲取样。只读显示层，不发回后端。
- 不改 `differenceMap`、`binaryMask`、区域面积、`rankScore` 与掩码资格；加入掩码、精算、交替对比都不受开关影响。
- 灰度取分析网格的 0..255 显示灰度。盘阵预览 JPG 逐图做过直方图均衡，不能跨图比较绝对亮度，也不能当成原始 DN；需要真 DN 时用原始 ROI 精算。
- 关闭时不计算排序、不改变候选顺序，区域上仍保留统计，开关可以立即切换。

验证：新增 `src/lib/__tests__/diffTone.test.ts` 17 项（smoothstep 边界与单调、四个隶属度、权重上下限与平坦度影响、掩码 / 有效像素 / 空区域、跨分辨率矩形、冷暖色插值）；`diffStore.test.ts` 新增 2 项（关闭保持后端顺序、开启按复核权重排序且原数组不变；分析结果附带归因统计）；前端全量 67 files / 841 passed，`npm run check:terms`、`vue-tsc --noEmit` 与 `npm run build` 通过。浏览器回归 `node .e2e/test-diff-tone.js`（先构建）用左暗右中灰的合成影像验证：默认关闭时保持后端顺序，打开后中间调平坦区域排到前面、两行都出现权重条、切换不需要重新分析；截图 `.e2e/artifacts/diff-tone-weight.png`。真实盘阵灰度与多景列表的观感仍待内网验收。

### 逐像素加权与滑动窗口（2026-11-06 补充）

上一节的权重原先只改候选排序和选中轮廓，热力图分布不动。用户要求「非线性走逐像素加权」，现补充显示层实现：

- **逐像素权重**：每个像素用滑动窗口取 A 侧局部均值与标准差，以及两侧窗口均值差 `Δ = mean(B) − mean(A)`，套用同一套 smoothstep 隶属度与 `w_mid · w_dark` 公式。热力图强度按 `差异 × w` 着色，超过 1 截断到最暖色。
- **动态窗口**：窗口半径按分析网格短边自适应（短边 / 300，夹在 2–8 像素），在分析网格坐标里滑动，与画布缩放无关；同一次分析只算一次并缓存。
- **实现**：`lib/diffTone.ts::toneWeightMap` 用行式盒式滤波（水平前缀和进环形缓冲 + 垂直逐列滑动和）计算局部统计，内存只与网格宽度相关；`lib/diffRender.ts::colorizeHeatBytes` 负责加权着色。权重字节在 0.3–1.8 区间线性量化，1.0× 精确落在 119，中性像素不会因量化微亮。
- **结果存储**：分析完成后把两图裁剪后的灰度压成 Uint8 与原始差异字节一起留在 store；热力图画布从原始差异重建，开关切换不重新请求后端、不重新解码 PNG。权重图在第一次开启时才计算；之后开关直接用缓存。
- **原始 ROI 精算**：前端拿不到源 TIFF 灰度，按归一化坐标把两张预览缩略图重采样到长边 ≤ 512 的共同小网格后再算权重，最后平滑放大到结果网格；避免把缩略图直接放大后局部标准差在块内塌成 0、块边骤升。
- **不改测量**：`differenceMap`、`binaryMask`、区域面积、`rankScore` 与掩码资格仍不变；开关只重建热力图显示层。图例在开启时多一行「逐像素亮度归因 ×0.3–1.8；差异乘权重后超过 1 截断」。

验证：`diffTone.test.ts` 新增 7 项（窗口半径自适应与夹紧、平坦中间调上限、纹理区降权、暗部提亮下限、NoData 中性且不污染邻点、尺寸不一致拒绝、Uint8 灰度输入）；`diffRender.test.ts` 新增 3 项（逐像素乘权重后与等价强度同色、超过 1 截断、NoData 保持透明）；`diffStore.test.ts` 新增 1 项（开关重建热力图且不重新分析）。前端全量 69 files / 866 passed、`npm run typecheck` 与 `npm run build` 通过。浏览器回归 `node .e2e/test-diff-tone.js` 在开关前后直接采样热力图画布：中间调平坦区颜色由 `[182,57,116]` 变为 `[252,212,111]`，暗部保持 `[182,57,116]` 不变，并检查图例新增说明。2048×1536 的权重图首次计算约 0.3 秒（纯前端同步计算），属一次性开销；真实盘阵大图的观感与开关响应仍待内网验收。
